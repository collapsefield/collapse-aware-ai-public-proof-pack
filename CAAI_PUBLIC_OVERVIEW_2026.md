# Collapse Aware AI — Public Overview (2026)

**Company:** Inappropriate Media Limited, trading as Collapse Aware AI  
**Status:** Public-safe engineering and commercial overview  
**Updated:** 27 August 2026

Collapse Aware AI (CAAI) is proprietary middleware for **governed retained-state behavioural selection**.

Its purpose is not simply to remember more. CAAI controls whether relevant retained history should be allowed to influence **which permitted behaviour wins**, while preserving a clean current-task/reference path and an inspectable decision record.

> **Retained history is eligible evidence, not automatic authority.**

---

## The engineering distinction

A host application can already know what actions, responses or interventions are permitted.

CAAI adds a separate continuity and selection layer that can:

- retain compact state across time;
- revise, supersede or revoke outdated retained state;
- judge whether prior state is relevant to the present situation;
- prevent retained history from dominating simply because it exists;
- compare history-conditioned behaviour against a clean current-task/reference behaviour;
- route the final decision through a governed selector;
- preserve bounded evidence of what was selected and which retained state was eligible to matter.

The host remains authoritative for domain truth, the permitted candidate/action set and external execution.

# Core Gold Build — frozen commercial selector foundation

The **CAAI Core Gold Build** is the frozen selector foundation currently available for commercial evaluation, pilot and licensing discussions.

Public-safe accepted capabilities include:

- selection among host-supplied permitted candidate behaviours/actions;
- reference and governed retained-state operating conditions;
- retained-state persistence and recall across restart;
- deterministic replay in tested conditions;
- retained-state revision and revocation;
- bounded fallback and validation behaviour;
- durable decision identity and Decision Records in the integrated evaluation lineage;
- customer-safe evidence projection;
- duplicate/replay/restart protection in the accepted managed-evaluation stack;
- guided managed evaluation with customer-safe evidence export.

The Core Gold value proposition is deliberately narrow:

> **A host supplies permitted choices; CAAI governs whether retained history should change which permitted choice wins.**

That makes it relevant to AI agents, simulations, NPC/game systems, adaptive workflows and other runtimes where history should influence behaviour without becoming an unrestricted prompt or hidden authority.

# Evolution 2 — richer continuity engineering branch

**Evolution 2 (E2)** extends the retained-state architecture beyond the frozen Core Gold selector while keeping final authority outside the language model.

The current private engineering line includes accepted checkpoints for:

- a structured **ContinuityFrame** interpretation layer;
- bounded hybrid retained-state retrieval;
- **Open Loops** for genuinely unfinished matters;
- conservative **Reopen Semantics** for resolved matters that genuinely become active again;
- **Interaction Fit** so relevant history can still be withheld when it is inappropriate to the present interaction;
- suppression and bounded proactive controls to reduce repetition and unwanted callbacks;
- **Confidence / Clarification** gates that can hold uncertain history rather than silently treating it as authoritative;
- conservative **Contradiction / Change Surfacing**;
- **Outcome Recording** that keeps selected/proposed behaviour separate from host-confirmed execution;
- **Agent Self-History** for selected agent claims, commitments, decisions and actions without allowing losing candidates to write history;
- richer turn-local behavioural signals that can influence style/caution without becoming permanent truth or personality labels;
- a consent-gated **Session Observation** foundation;
- an engineering tuning console with real config-backed controls and protected invariants;
- a local Engineer Model package with text and microphone speech-to-text input;
- restart-safe local operation and a clean engineering baseline for longitudinal human testing.

Evolution 2 remains an **Engineering build rather than a finished Production release**. Its purpose is to validate richer continuity behaviour before any production freeze.

## Why the clean reference matters

A central CAAI design principle is that retained history must compete with a clean current-task/reference path.

That means a system can remember something important and still decide **not** to use it when the present task is better served by a clean response or action.

This is particularly important for long-running agents and NPCs: good continuity is not maximum memory use. It is **selective, governed influence**.

---

## Game / NPC relevance

Games are a natural fit because the host already owns structured world truth:

- exact player and NPC identities;
- quests and unresolved matters;
- witnessed events;
- world state and locations;
- permitted actions;
- save/restart boundaries.

A game can keep those authorities while using CAAI to decide whether retained player/NPC history has earned the right to change the current permitted behaviour.

The current commercial selector lane and the richer E2 continuity lane can therefore be evaluated separately or together. CAAI is not presented as a finished Unity, Unreal or Godot SDK today; the architecture is host-neutral so buyer-specific adapters can remain thin.
