# Collapse Aware AI — Current Engineering State

**Date:** 27 August 2026  
**Status:** Public-safe current-state record  
**Company:** Inappropriate Media Limited, trading as Collapse Aware AI

## Current position

Collapse Aware AI (CAAI) is proprietary middleware for **governed retained-state behavioural selection**.

The current engineering programme now has two clearly separated layers:

1. **Core Gold Build** — the frozen commercial selector foundation.
2. **Evolution 2** — the richer continuity engineering branch built around the same principle that retained history must not automatically become final authority.

> **Retained history is eligible evidence, not automatic authority.**

---

# 1. Core Gold Build

The Core Gold Build remains frozen as the accepted selector foundation rather than being continually rewritten as new research is added.

Public-safe accepted capabilities in the current integrated lineage include:

- selection among host-supplied permitted candidate behaviours/actions;
- reference and governed retained-state conditions;
- persistence and recall across restart;
- deterministic replay in tested conditions;
- retained-state revision and revocation;
- validation and bounded fallback behaviour;
- real final selection through the frozen selector path;
- durable decision identity and private Decision Records;
- customer-safe Decision Record projection;
- restart, replay, duplicate-protection and reconciliation hardening;
- guided managed-evaluation packaging;
- customer-safe JSON / HTML / PDF evidence export.

The host remains responsible for domain truth, candidate generation / permitted action sets and external action execution.

Core Gold is commercially discussable for:

- controlled technical demonstrations;
- paid managed evaluations;
- buyer-specific bounded test scenarios;
- pilots;
- integration discussions;
- licensing discussions.

The proprietary selector source and private scoring/tuning details are not public.

# 2. Evolution 2

Evolution 2 extends the architecture around the frozen selector with richer continuity, lifecycle and behavioural controls.

The private engineering line now includes accepted checkpoints for:

- structured ContinuityFrame interpretation;
- bounded hybrid retained-state retrieval;
- Open Loops for unfinished matters;
- conservative Reopen Semantics;
- Interaction Fit between retained state and the present interaction;
- suppression and bounded proactive controls;
- Confidence / Clarification gates;
- conservative Contradiction / Change Surfacing;
- record-only Outcomes integration;
- Agent Self-History written only from finally selected behaviour;
- richer turn-local behavioural signals with bounded authority;
- consent-gated Session Observation foundation;
- a config-backed Engineering Tuning console;
- restart-safe local Engineer Model packaging;
- local microphone speech-to-text input for the engineering chat interface.

A clean current-task/reference behaviour remains a genuine competitor to history-conditioned alternatives, and final selection authority remains separated from candidate generation.

Evolution 2 is currently an **Engineering build, not a finished Production release**.

## Why this matters

Ordinary memory systems focus on what to store and retrieve.

CAAI focuses on a different problem:

> **When should retained history be allowed to change current behaviour, and when should the system deliberately ignore it?**

That distinction matters for long-running agents, NPCs, simulations and adaptive workflows where stale, irrelevant or over-dominant memory can be as damaging as forgetting.

---

## Game / NPC direction

CAAI is host-neutral by design.

Game and simulation hosts can supply authoritative world state such as:

- player/NPC identities;
- quests and unresolved matters;
- witnessed events;
- current locations/state;
- permitted actions;
- save/restart identity.

The game remains authoritative for world truth and execution. CAAI can then govern whether retained history should influence which permitted behaviour wins.

The current public position is **game/NPC evaluation and adapter potential**, not a claim that a finished Unity/Unreal/Godot production SDK already exists.
