# Collapse Aware AI — Public Scope Response and Claim Boundaries

**Project:** Collapse Aware AI (CAAI)  
**Maintainer:** Marcos Verrell Moss Ross (M.R.) / Inappropriate Media Limited  
**Status:** Public-safe clarification note  
**Purpose:** Address common technical and scientific questions without disclosing Crown internals.

---

## Summary

Collapse Aware AI is not presented as a new foundation model, a sentient system, or proof of a consciousness theory.

CAAI is a middleware architecture for governed, memory-weighted behavioural selection. It is designed to sit between a host application and an underlying model, scripted agent, NPC system, or decision engine.

The engineering claim is deliberately narrower than the wider Verrell's Law research programme:

> CAAI tests whether retained state, weighted memory, continuity anchors, and governor constraints can measurably influence runtime behaviour without retraining or modifying the base model weights.

That is the public-safe claim.

---

## What CAAI Solves

CAAI is aimed at practical runtime problems:

- behavioural drift across interactions
- inconsistent long-running agents
- NPCs or assistants that forget prior state
- repeated prompt-stuffing to maintain continuity
- uncontrolled variation between sessions
- difficulty auditing why a behaviour changed
- high cost from retraining, manual tuning, or ever-growing context prompts

The system focuses on continuity, memory weighting, behavioural stability, governed decision-making, and controlled adaptation.

---

## What CAAI Does Not Claim

CAAI does not claim that:

- the underlying model understands everything
- middleware can create intelligence the base model lacks
- hallucinations are caused by quantum or field effects
- consciousness has been proven
- the Crown kernel is open-source
- Phase-1 is a full production SDK
- governed behaviour means semantic moral understanding

If the underlying model lacks knowledge, reasoning ability, or domain competence, CAAI does not magically create those abilities.

CAAI is designed to help capable systems behave more consistently over time.

---

## Difference From a System Prompt

A detailed system prompt is mostly static.

CAAI is designed as a runtime behavioural layer. Publicly described functions include:

- retaining selected state
- weighting memory by relevance and continuity
- influencing candidate selection
- applying governor constraints
- reducing uncontrolled drift
- supporting measurable divergence between governed and non-governed runs

A system prompt says what the system should do.

CAAI is intended to influence what the system selects and preserves over time.

---

## Cost and Training Position

Training is expensive. Re-training is often even more expensive.

CAAI aims to move a significant portion of behavioural adaptation into the runtime layer, reducing reliance on repeated retraining, expanding prompts, manual retuning, and bespoke scripting.

For games, simulations, agent systems, and long-running assistants, the commercial value is expected to come from:

- lower prompt-maintenance overhead
- less duplicated scripting
- less repeated behavioural tuning
- greater reuse of existing models
- more stable long-term behaviour
- easier demonstration of governed versus unguided behaviour

This is a cost-reduction and control layer, not a replacement for model capability.

---

## Relationship to Verrell's Law

Verrell's Law provides the broader theoretical inspiration: retained information from prior states may bias later selection.

CAAI implements a narrower engineering version of that idea:

> retained runtime state can be weighted and used to influence future behavioural selection.

CAAI does not require the strongest speculative physics claims of Verrell's Law to be true in order to be useful as middleware.

The software claim stands or falls on runtime evidence: whether governed, memory-weighted selection produces measurable behavioural difference under controlled conditions.

---

## Current Evidence Direction

Public evaluation should focus on:

- bias ON versus bias OFF comparisons
- governed versus non-governed selection
- restart and persistence tests
- continuity over repeated interactions
- drift reduction
- controlled replay variance
- route evidence from host UI to API/scaffold to adapter to Crown and back

Private/NDA evidence may include fuller request and response bodies, raw scoring traces, logs, and Crown-level diagnostics.

Public material should remain buyer-safe and should not expose private scoring formulas, Crown internals, sealed request schemas, or proprietary implementation details.
