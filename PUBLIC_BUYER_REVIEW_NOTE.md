# Public Buyer Review Note

**Updated:** 7 August 2026

## Purpose

This note is for technical reviewers, licensing partners, agent-framework teams, simulation teams, game / NPC teams and enterprise evaluators reviewing Collapse Aware AI from public material.

Collapse Aware AI should be evaluated as an engineering system.

Verrell’s Law is a separate retained-state selection research framework. A buyer does not need to accept any wider physical interpretation in order to evaluate the middleware.

---

## Clean evaluation position

Collapse Aware AI is proprietary middleware for **retained-state behavioural selection**.

The practical question is:

> **Can relevant retained prior state change which permitted behaviour wins, while the reference path and resulting evidence remain inspectable?**

That is the evaluation centre.

---

## Current technical position

The engineering line has progressed beyond the original Phase-1 Core Gold foundation into a **local managed-evaluation package**.

Current public-safe evidence includes:

- real selection through the sealed Core/Crown pathway;
- reference-versus-governed retained-state comparison;
- persistence and deterministic replay;
- versioned retained-state revision / revocation;
- continuity memory and session boot;
- bounded recall-quality and ambiguity controls;
- durable private Decision Records;
- customer-safe Decision Record projection;
- restart/replay/duplicate/reconciliation hardening;
- guided managed-evaluation workflow;
- customer-safe JSON, HTML and PDF comparison exports.

A controlled synthetic live comparison held the prompt, candidate set, candidate order, mapped thread and deterministic seed constant. The reference condition selected one permitted candidate and the governed retained-state condition selected another.

That demonstrates **live end-to-end behavioural divergence through the real selector path**.

The comparison changed both operating mode and retained-state-influence configuration, so it is not presented as isolated causal proof of either factor alone.

---

## What to evaluate

A serious technical review should focus on:

- candidate-set integration;
- retained-state lifecycle and correction;
- reference-versus-governed comparison;
- persistence and restart behaviour;
- deterministic replay in controlled conditions;
- wrong-scope / revoked-state blocking;
- durable Decision Records;
- customer-safe evidence projection;
- failure transparency;
- duplicate protection and ambiguous-outcome reconciliation;
- integration feasibility with the buyer’s existing candidate/action system.

These are software questions.

---

## Best-fit evaluation shape

A suitable buyer already has, or can define:

1. a current event / situation;
2. multiple legitimate permitted behaviours or actions;
3. retained history that may legitimately matter;
4. a baseline/reference path;
5. a need to understand whether history changes final selection.

The host keeps responsibility for candidate generation, domain truth and external action execution.

CAAI controls the retained-state selection/evidence layer.

---

## Current commercial route

The preferred near-term route is a **paid, bounded managed evaluation** under appropriate confidentiality terms.

A managed evaluation can use synthetic data or a buyer-supplied bounded scenario and produce:

- reference selection evidence;
- governed retained-state selection evidence;
- durable decision linkage;
- customer-safe comparison records;
- a buyer-safe evidence export.

The proprietary Crown implementation remains under CAAI control.

---

## What not to confuse it with

CAAI is not presented as:

- a foundation model;
- AGI;
- machine consciousness;
- ordinary memory storage;
- a vector database;
- a standard RAG layer;
- a chatbot skin;
- public SaaS;
- finished multi-tenant production infrastructure;
- universal emotion / deception detection;
- proof of new physics;
- proof of the full scientific scope of Verrell’s Law.

The middleware can succeed or fail on engineering evidence alone.

---

## Public/private boundary

Public materials describe the architecture, status, evidence logic and commercial boundary while protecting:

- Crown source;
- private scoring / weighting implementation;
- exact thresholds and tuning;
- unrestricted Decision Record internals;
- credentials / secrets;
- private runtime and deployment packages.

This repository is an evaluation and proof-orientation layer, not an open-source release.
