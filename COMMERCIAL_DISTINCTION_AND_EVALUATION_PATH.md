# Commercial Distinction and Evaluation Path

**Founder / Systems Architect:** Marcos Ross  
**Organisation:** Inappropriate Media Limited / Collapse Aware AI  
**Status:** Public commercial and technical orientation note  
**Updated:** 2026-08-07

---

## 1. Core distinction

Collapse Aware AI (CAAI) is not positioned as a general claim that memory matters in AI.

CAAI is narrower and more practical:

> **CAAI is middleware for retained-state behavioural selection.**

The important distinction is not merely storing or retrieving memory. The important distinction is allowing relevant retained prior state to influence **which permitted behaviour wins**, while keeping the reference path and resulting evidence inspectable.

---

## 2. What CAAI is not

CAAI is not:

- a foundation model;
- a vector database;
- a standard RAG pipeline;
- long-context prompting;
- ordinary memory storage;
- a chatbot skin;
- a claim of AGI or machine consciousness;
- a universal emotion / deception detector;
- proof of the full scientific scope of Verrell’s Law;
- public SaaS or finished multi-tenant production infrastructure.

CAAI is an engineering layer around runtime behavioural selection.

The current private engineering line is no longer limited to the original Core Gold demonstration.

```text

        ↓

        ↓

        ↓
```

The host remains responsible for candidate generation, domain truth and external action execution.

## 4. What has been demonstrated

Public-safe current evidence includes:

- retained-state influence through the real selector path;
- reference and governed comparison under controlled matched inputs;
- persistence and deterministic replay;
- revision / revocation and recall-quality controls;
- durable private Decision Records;
- customer-safe Decision Record projection;
- failure / replay / restart hardening;
- duplicate protection and ambiguous-outcome reconciliation;
- customer-safe JSON, HTML and PDF managed-evaluation exports.

A controlled synthetic live evaluation held the prompt, candidate set, candidate text/order, mapped thread and deterministic seed constant. The reference condition selected one permitted candidate; the governed retained-state condition selected another.

That is evidence of **live end-to-end behavioural divergence** under the declared comparison conditions.

The comparison changed both operating mode and retained-state-influence configuration, so it is not presented as isolated single-factor causality.

## 5. Current commercial target

The strongest commercial fit is a system that already has several legitimate actions, behaviours, interventions or outputs and needs history to influence final selection without making the decision path opaque.

Examples include:

- agent / voice-agent runtime teams;
- simulation and training systems;
- game / NPC systems;
- adaptive learning systems;
- compliance / audit-sensitive runtime systems;
- bounded intervention-selection systems;
- enterprise R&D teams evaluating retained-state continuity.

The public market story should remain centred on the engineering problem, not a long catalogue of sectors.

---

## 6. Paid managed evaluation path

The preferred near-term commercial step is a **paid bounded managed evaluation** under appropriate confidentiality terms.

A buyer supplies or agrees:

1. a bounded scenario;
2. a current event/state;
3. a permitted candidate set;
4. any relevant retained-history fixture;
5. a baseline/reference condition;
6. acceptance questions.

CAAI operates the protected runtime and returns an evidence package showing:

- reference selection;
- governed retained-state selection;
- durable decision linkage;
- customer-safe evidence;
- comparison result;
- known boundaries and failure status.

The buyer does not need unrestricted access to Crown source in order to evaluate fit.

---

## 7. What the evaluation should answer

The evaluation should answer practical questions such as:

- Does relevant retained state alter final selection in a useful way?
- Does the comparison remain inspectable against a reference condition?
- Are corrections / revoked state handled appropriately?
- Does the state and evidence survive restart?
- Are failures reported honestly?
- Can the middleware map cleanly into the buyer’s candidate/action architecture?
- Does the buyer gain useful continuity or policy control without replacing its existing model/runtime?
